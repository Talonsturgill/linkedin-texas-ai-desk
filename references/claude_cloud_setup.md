# Texas Desk cloud environment

The saved routine reads the release branch named in its thin instructions. Select the dedicated
Texas Desk environment, Haiku 5.5, and only the Gmail connector. Keep draft-only delivery and
Auto-fix pull requests off. The existing schedule is Wednesday at 4:04 AM Eastern.

Use Custom network access with the exact public hosts in `config/claude_source_domains.txt`.
Keep "Also include default list of common package managers" enabled for dependencies, GitHub,
and immutable image verification. The list covers the source catalog, ordinary www redirects, public release wires, and reviewed
hosts identified during the live test;
it does not grant unrestricted internet access. No secrets or credentials are required for coded
artwork. Keep `CLAUDE_CODE_EFFORT_LEVEL=medium` in the environment; project settings also request
medium effort. Record any mismatch in the actual session control rather than claiming a measured
serving configuration from these files.

The main Claude Code page exposes the environment selector. Open Cloud, focus Texas Desk, and
press the right arrow to edit its environment. In the editor, select Custom, paste the host list,
preserve the default package-manager checkbox and existing environment values, then save.
Verify the saved values by reopening the editor. A routine's environment dropdown can be used
for selection; the main-page selector exposes the edit action more reliably.

Preflight must fetch an actual primary page and an independent page. Search snippets and tool
availability do not prove source access. A host-specific rejection permits another source, not
inference about the rejected page. A denied network policy is a setup failure, not an editorial
no-target result. Never alter proxy settings, disable TLS checks, or route around access controls.
New source domains require a reviewed environment update; the routine does not widen its own
network permissions.

The behavior is documented in [Claude cloud environments](https://code.claude.com/docs/en/cloud-environments#allow-specific-domains).
